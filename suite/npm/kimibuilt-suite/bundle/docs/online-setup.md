# KimiBuilt Suite Online Setup

KimiBuilt Suite is delivered as an online compose stack plus thin package
wrappers. The operator edits one `release.env` file, keeps it on the target
server, and gives users only the login URL plus the credentials they need.

## Package Choices

| Channel | Best for | Entry command |
| --- | --- | --- |
| Compose bundle | Linux server or VPS install | `./install-compose.sh --yes` |
| npm package | Node-based install and smoke checks | `kimibuilt-suite install --yes` |
| Homebrew formula | macOS/Linuxbrew trial install | `kimibuilt-suite install --yes` |
| Lilly compatibility npm package | Existing Lilly Suite users | `lilly-suite install --yes` |

## Setup Flow

1. Install Docker Engine or Docker Desktop with Docker Compose v2.
2. Unpack the compose bundle, or install the npm/Homebrew package.
3. Generate the release environment:

```bash
kimibuilt-suite install --no-start --print-secrets
```

For a raw bundle:

```bash
./install-compose.sh --no-start --print-secrets
```

4. Edit `release.env` and set the public online URL:

```dotenv
KIMIBUILT_PUBLIC_ORIGIN=https://agents.example.com
API_BASE_URL=https://agents.example.com
KIMIBUILT_ALLOWED_ORIGINS=https://agents.example.com
```

5. Add the required AI provider key:

```dotenv
OPENAI_API_KEY=replace-with-your-openai-or-gateway-key
```

6. Start the stack:

```bash
kimibuilt-suite install --yes
```

7. Open the online URL and sign in with:

```text
Username: value of KIMIBUILT_AUTH_USERNAME
Password: value of KIMIBUILT_AUTH_PASSWORD
```

## Password And Token Map

| Setting | Who uses it | How it is supplied |
| --- | --- | --- |
| `KIMIBUILT_AUTH_USERNAME` | Browser login | Defaults to `admin` |
| `KIMIBUILT_AUTH_PASSWORD` | Browser login | Generated by installer |
| `KIMIBUILT_JWT_SECRET` | Signed browser sessions | Generated by installer |
| `KIMIBUILT_FRONTEND_API_KEY` | CLI, WebSocket, automation clients | Generated by installer |
| `SESSION_SECRET` | Express/session safety | Generated by installer |
| `POSTGRES_PASSWORD` | Local Postgres service | Generated by installer |
| `KIMIBUILT_REMOTE_RUNNER_TOKEN` | Remote runner callbacks | Generated by installer |
| `OPENAI_API_KEY` | Chat, tools, and agents | Provided by operator |
| `OPENAI_MEDIA_API_KEY` | Optional image/video generation | Provided by operator |
| `PERPLEXITY_API_KEY` | Optional web research | Provided by operator |
| `REMOTE_CLI_MCP_BEARER_TOKEN` | Optional remote deployment gateway | Provided by operator |

The installer prints masked values by default. Use `--print-secrets` only on a
trusted terminal when you need a one-time credential handoff. The durable source
of truth is the generated `release.env` file on the server.

## Online Handoff

Give the end user:

- The online URL, for example `https://agents.example.com`.
- The browser username and password.
- A note that API clients use `KIMIBUILT_FRONTEND_API_KEY` as a bearer token.
- A support contact or rotation procedure for the operator-owned provider keys.

Do not send `release.env` wholesale to normal users. It contains database,
provider, API, and remote runner secrets.

## Verification

```bash
docker compose --project-name kimibuilt-suite --env-file release.env --file compose.yaml ps
curl -fsS https://agents.example.com/health
curl -fsS https://agents.example.com/ready
```

For local trials, use `http://localhost:3000` in place of the public URL.
